# Алгоритмы и структуры данных 

Небольшое интерактивное приложение на Python для изучения классических алгоритмов (Фибоначчи, факториал, сортировки) и структур данных (стек с минимумом, очередь на двух стеках) через удобный CLI-интерфейс. 

## Использование

### Установка

Проект использует `uv` для управления виртуальным окружением и `Makefile` для автоматизации команд.

**Требования:**

- Python 3.13+
- `make`
- `uv` (устанавливается командой `pip install uv`)

**Установка зависимостей**

```bash
make install
```

### Запуск приложения

Через `Makefile`:

```bash
make run
```

Напрямую через `uv`:

```bash
uv run main.py
```

### Тестирование и бенчмарки

- Юнит‑тесты:

```bash
make test
```

- Бенчмарки (через `pytest-benchmark`):

```bash
make bench
```

## Архитектура проекта

```text
.
├── main.py
├── adapter/        # Слой взаимодействия с пользователем (CLI, Questionary)
├── domain/         # Алгоритмы и структуры данных
├── pkg/annotools/  # Утилиты для typing.Annotated и валидации
├── test/           # Тесты и бенчмарки
├── Makefile
├── pyproject.toml
└── uv.lock
```

### Основные компоненты

- `domain/algo/`
  - Итеративная и рекурсивная реализация Фибоначчи и факториала.
- `domain/sort/`
  - Реализации алгоритмов сортировки: пузырьковая, быстрая, поразрядная, подсчётом, кучей и карманная.
- `domain/structures/`
  - `MinStack` — стек с получением минимума за \(O(1)\).
  - `TwoStackQueue` — очередь, реализованная через две стека.
- `adapter/cli/`
  - `main.py` — регистрация всех доступных команд через декоратор `@cli`.
  - `cli.py` — небольшой фреймворк‑обёртка над функциями: парсит аннотации, задаёт вопросы пользователю и запускает доменную логику.
  - `ask.py` — вспомогательная функция для опроса пользователя и приведения типов.
  - `style.py` — общая стилизация Questionary‑промптов.
  - `validator.py` — валидаторы значений (числа, диапазоны, и д.р.).
- `pkg/annotools/`
  - Утилитарный пакет для работы с `typing.Annotated`, валидацией аргументов и метаданными, независимый от конкретного UI.
- `test/`
  - Набор тестов для алгоритмов, структур данных и бенчмарков производительности.

### Поток выполнения команд

1. Пользователь запускает приложение (`make run` или `uv run main.py`), после чего управление передаётся в `adapter.cli.main`.
2. Функции в `adapter.cli.main.py` регистрируются через декоратор `@cli`; каждая такая функция становится отдельной командой в интерактивном меню.
3. Для функций с аргументами CLI считывает `typing.Annotated` и извлекает из них валидаторы и метаданные (через `annotools` и собственные валидаторы).
4. Пользователь отвечает на вопросы в терминале (Questionary‑инпуты, выбор из списка и т.п.), значения проходят валидацию и приводятся к нужным типам.
5. После успешной валидации вызывается соответствующая функция из `domain`, а результат отображается пользователю.

### Обработка ошибок

- Ошибки неправильного ввода отлавливаются на уровне валидаторов (`NumValidator`, `TypeValidator`, `MinValue`, `MaxValue`, их float‑аналоги).
- При некорректных значениях пользователь остаётся в текущем вопросе и получает понятное сообщение об ошибке; приложение не падает и позволяет повторить ввод.
- Для структур данных (стек, очередь) граничные случаи (попытка взять элемент из пустой структуры) обрабатываются и отображаются в UI, не прерывая работу всего приложения.

## Annotools

`annotools` небольшой утилитарный пакет для работы с `typing.Annotated`, валидацией аргументов и добавлением метаданных без привязки к конкретному UI‑фреймворку (подробности в [`pkg/annotools/README.md`](pkg/annotools/README.md)). Концептуально пакет опирается на идею PEP 593: `Annotated` позволяет прикреплять произвольные метаданные к типам, которые могут использоваться как статическими анализаторами, так и рантайм‑библиотеками.

В этом приложении `annotools` используется для:

- описания ограничений прямо в аннотациях параметров (минимум/максимум, тип, сообщения пользователю).
- извлечения этих метаданных при запуске команды и автоматической сборки вопросов для пользователя.
- унифицированной валидации аргументов независимо от того, как именно эти аргументы были получены.

## Расширяемость

### Добавление нового алгоритма или команды

Чтобы добавить новую команду в CLI:

1. Реализовать функцию в одном из модулей `domain` (например, новую сортировку или алгоритм).
2. Описать её параметры с помощью `typing.Annotated`, добавив нужные валидаторы и метаданные (`NumValidator`, `TypeValidator`, `MinValue`, `MaxValue`, `Message` и т.д.).
3. Импортировать функцию в `adapter/cli/main.py` и обернуть её в декоратор `@cli`, указав человекочитаемое docstring описание (оно пойдёт в help/меню).
4. При необходимости добавить интерактивный сценарий (как для стека/очереди), используя компоненты Questionary.
5. Написать тесты в `test/` и при необходимости бенчмарки с использованием `pytest-benchmark`.
